# Qwen3.8 Flash-Next 单卡 Modal 配置与成本分析

> 2026-11-04 基于历史实际运行 JSON 重算。本报告中的硬件数据均来自旧 v1 Volume 时期的模型运行；2026-11-04 切换到纯 Volume v2 后，**没有重新运行任何模型**，所以不能把历史加载速度标注为 v2 实测。
>
> 原始记录位于 `results/qwen_flash_next/infer_*.json`，所有测试使用 `RTX-PRO-6000`、Penny Royal v3.1.5、Qwen3.8-Flash-Next-NVFP4、PLE RAM offload、8 GB HiCache。

## 结论

**最佳已验证的低成本申请配置：1× RTX PRO 6000 Blackwell、4 Modal 物理 CPU 核、80 GiB RAM、8 GB HiCache、PLE CPU RAM 卸载。**

其余量边界：加载阶段实际 CPU RAM 峰值约 107.75 GiB，运行末段 RAM 约 66.5 GiB，GPU 显存峰值约 80.9 GiB。80 GiB 是申请量，**不是实际峰值**。Modal 的 CPU/RAM 收费规则是每一计费时段取 `max(request, measured usage)`，因此短暂超额使用会增加费用。

## 计费公式与口径

本报告采用 Modal 官网普通 Function 基础费率（2026-11-04）：
- RTX PRO 6000：$0.000842/GPU 秒
- CPU：$0.0000131/物理 CPU 核秒
- RAM：$0.00000222/GiB 秒

对于每次实验：

```text
GPU_cost ≈ GPU_runtime_s × 0.000842
CPU_cost ≈ 4-or-8_reserved_cores × GPU_runtime_s × 0.0000131
RAM_cost ≈ Σ [max(requested_GiB, sampled_actual_GiB) × sample_interval_s] × 0.00000222
estimated_total ≈ GPU_cost + CPU_cost + RAM_cost
```

使用 `elapsed_s` 作为 Function 内时长、1 秒采样的 `memory.current` 进行近似积分，开始和末尾沿用最近样本。实际 Modal 计费可能包括镜像/容器冷启动、idle keepalive、CPU 突发及独立资源用量，均由平台计费器决定，所以这是**重新计算的实验估算，不是发票**。上述 5 次试验合计约 $1.624，仅含各自远程函数内的估算计算费，未计模型下载、探针、镜像准备等。

80 GiB / 4 核组拆分约为：
- GPU $0.2202
- CPU $0.0137
- RAM $0.0469
- 总计约 **$0.2809**；RAM 超出 80 GiB 申请量所增加的费率积分约 $0.0005。

## 相同运行时长下的资源价格

| 同一小时持续占用 | GPU | CPU | 内存保底 | 合计 |
|---|---:|---:|---:|---:|
| 128 GiB + 8 核 | $3.0312 | $0.3773 | $1.0230 | **$4.4315/h** |
| 96 GiB + 8 核 | $3.0312 | $0.3773 | $0.7672 | **$4.1757/h** |
| 80 GiB + 8 核 | $3.0312 | $0.3773 | $0.6394 | **$4.0478/h** |
| **80 GiB + 4 核** | **$3.0312** | **$0.1886** | **$0.6394** | **$3.8592/h** |

因此，相比最初的 128 GiB + 8 核，名义费率降低 $0.5723/h，约 **12.9%**，还需加上短暂超额 RAM 的实际计费。

80→64 GiB 即使完全成功，每小时理论最多减少约 **$0.128** 的内存申请费；鉴于已观测的 ~66.5 GiB 末段内存和 ~107.75 GiB 加载峰值，这种降配的可得收益有限，生产使用不建议未经测试采用。
