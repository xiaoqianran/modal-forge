## 3. 长输入与双并发

| 负载 | 输入 tokens | TTFT | Decode tokens/s | 结果 |
|---|---:|---:|---:|---|
| 中等长度 | 8,578 | 7.172s | 360.58 | 正确 |
| 较长输入 | 26,628 | 1.723s | 335.80 | 正确 |
| 两个短请求同时提交 | 20 + 14 | — | **281.30 聚合 tok/s** | 两个都正确 |

两项长输入使用重复英文片段加算术指令，容易命中前缀缓存。因而 26K 输入的 TTFT 更短不能当作一般性的长文本首 Token 性能。测试覆盖最大约 26.6K tokens，**没有验证 128K/256K 甚至 1M**。双并发仅两个极短请求、没有长时压力测试和高并发 SLA。

## 4. 目前的最佳配置及后续方向

当前最佳**已跑通的低成本配置**依旧为 **80 GiB RAM + 4 CPU 核 + 1×RTX PRO 6000**。换成 v2 后同样成功；GPU 显存约 80.9 GiB、RAM 加载峰值约 107.7 GiB。

该配置按申请量计算的长期基础单价约 $3.86/h，实际超额 RAM 与 CPU 用量另计。若目标是频繁短时启动，当前更大的成本浪费来自 4–6 分钟冷启动，而不是 4 核与 8 核的申请费率差。可优先考虑模型文件访问路径、镜像预热、持久化 GPU 容器，或延长空闲缩容间隔；这些措施都需要新一轮对照实验验证。
